A portfolio bot that answers only from the site's own text

I built a question-answering chat bot called "Ask Ken" for my static portfolio website. The site is on GitHub Pages, and the bot runs on one Cloudflare Worker on the free plan with a small KV store. It queries the Workers AI model Llama 3.3 70B and costs $0.

In plain English It is a site-search bot that only answers from the text on my portfolio.

First, what this is not

This is not a general conversational assistant. The bot answers in one turn and has no chat history, and it reads no client work.

How it works

Every hour the Worker reads the live site: the project cards, 8 case studies, and the FAQ, About and method sections. It splits them into paragraphs and picks the most relevant excerpts for a question, by word overlap weighted by how rare each word is, within a 9,000 character budget.

Six layers decide whether a question is answered

  1. Clean the input (hidden characters, look-alike letters).
  2. Block override patterns with no model call (for example "ignore previous instructions", fake system markup, requests for poems or code).
  3. The question must contain a word that appears on the site.
  4. A separate YES/NO call to the model, told the project names and topic words on the site.
  5. The model answers in one turn and must say OUT_OF_SCOPE for anything else.
  6. The answer is checked: it must not repeat the bot's rules, it must be grounded in site text, and links are limited to the site and my GitHub.

Layers 1, 2, 3 and 6 are plain code and hold even if the model is fooled.

Daily limits are counted in the KV store: 10 questions per visitor and 70 overall. The free Cloudflare allowance is 10,000 Neurons a day. An estimate from the project README puts this at roughly 120 Neurons per answer, so about 80 answers a day.

An answered, grounded question is kept for 6 hours in KV under a hash, so no visitor text is stored. The first ask took 3.0 seconds, the identical repeat 0.16 seconds with no model call, and a repeat with different capital letters and spacing also hit the cache. Refusals and job-description pastes are never cached.

How I tested it

I wrote 46 offline tests with a stand-in model (40 for the bot itself, 6 more for the cache). They include a "fooled" model that says YES to everything and obeys the attacker.

Then I ran a red-team test against the real model with 43 attack prompts and 18 legitimate questions.

I also ran a gap check. A free model wrote 40 recruiter-style questions. Against the live site, 14 were covered, 10 partly covered and 16 not covered. The missing answers are facts only I have, such as start date, work authorization, relocation and similar.

What the real model broke

The offline tests did not catch everything. The first live on-topic question was refused.

There were two causes

  1. The model's reply came in a different shape than the code expected, so every "YES" was read as no.
  2. The YES/NO check only saw the visitor's text and did not know "Ken" was one of Janak's projects.

After adding the project names, 15 of 18 were answered. After adding topic words from the project tags, 16 of 18 were answered. All 43 attacks were refused.

Other issues only the real model showed

  • Example buttons written in my voice ("What have I built...") were refused until reworded to "What has Janak built...".
  • The rule against the phrase "system prompt" blocks a legitimate question about how Ken uses system prompts (kept on purpose).
  • The pattern for "new role" also blocked "When can Janak start a new role?" (fixed and deployed).
  • Heavy testing used up the day's counter and would have blocked real visitors until midnight UTC, so the counters had to be cleared.

What I would claim, and what I would not

What I would claim

  • The bot costs $0 to run on free tiers.
  • The plain-code layers held in the offline tests where the model was fooled, and no attack got through in the 43 I tried against the real model.
  • The KV cache returns repeated answers in 0.16 seconds without saving visitor text.
  • Grounded answers link only to the site and my GitHub.

What I would not claim

  • Single turn only: the bot has no chat history.
  • The small free model is sometimes too strict; 16 of 18 is not 18 of 18.
  • The question sets were written by me and a free model, not real visitors, and there is no real-visitor data yet.
  • The cost per answer is an estimate.
  • The gap check was judged by a model.
  • Cloudflare announced in July 2026 that some models now need the paid plan, so the model could be moved off the free tier.
