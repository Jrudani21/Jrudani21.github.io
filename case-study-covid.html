Does a live COVID dashboard stay live when its data source stops?

My COVID-19 dashboard pulls from the public disease.sh API and says live in its title. I re-ran it against the real responses, saved on 6 Nov 2026. The history it plots ends in March 2023, one of its three chart choices is empty, and the freshness stamp does not measure the data.

What the dashboard does

Streamlit and Plotly over three disease.sh endpoints: the global totals, a historical series asked for with lastdays=180, and every country. It shows five numbers, a trend chart with a metric picker, the top 15 countries, a world map of cases per million and a searchable table. Each call is cached for ten minutes.

This is the cumulative series the dashboard plots, from the same endpoint. Switch to Recovered and move the slider. Then switch to full history to see where the dashboard's window sits.

Try the rankings

The dashboard ranks countries by total cases. Sort by per-million rates instead and the list changes almost entirely, which is why its map uses per-million and its bar chart does not.

    What re-running it found

    1. The "last 180 days" are three years old. The history endpoint ends on 9 Mar 2023, so lastdays=180 returns 11 Sep 2022 to 9 Mar 2023, whatever day you open the page. The chart title never says so.
    2. The Recovered option plots a flat line. Recoveries stop being reported after 20 Sep 2022, and the whole 180-day window is zero. A reader sees "recovered: 0" for a pandemic with hundreds of millions of recoveries.
    3. "Last refreshed" is the page clock. The caption uses datetime.now(), so it moves every time the app reruns. It tells you when the page drew, not how old the numbers are. The global feed itself reports zero new cases today.
    4. Nothing handles a failed call. Each fetch is requests.get(url).json() with no timeout and no status check. If the API errors or changes shape, the app dies with a traceback. In my own run, a script using Python's built-in urllib client was refused by the API with a 403 while curl was served, so a block is a realistic case.
    Why this matters: a dashboard can be correct code over a dead feed. The charts render, the caption looks fresh and nothing fails. Showing the data's own last date is the cheapest guard.

    What I changed

    The fixes are on the dashboard repo's master branch:

    • The data's last date is printed in the caption and the trend title, and the window is taken from the feed itself.
    • Recovered is gone from the picker, since the feed reports zero for it.
    • Every fetch has a 15-second timeout, a status check and a visible error instead of a traceback.
    • A second bar chart ranks by cases per million for countries with at least 1 million people.
    • The date window logic has a small test that runs without the network or Streamlit.
    Not verified: I could not start Streamlit here (the installed version fails to import), so the page itself has not been run. The helper and the per-million table were checked against the saved API response.

    Still open: showing a 7-day average of new cases beside the cumulative curve, and archiving a snapshot so the page can say so when the API is down.
