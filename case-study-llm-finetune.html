Building an eval that can say no: a held-out harness for a QLoRA fine-tune

I fine-tuned a small model on statistics questions. Before claiming it helped, I built a held-out test with an exact paired significance test and a separate LLM judge. Run on two base models, it correctly reports no significant difference. I then retrained the fine-tune and ran the real comparison: also no significant difference (see The real comparison).

First, what this is not

It is not evidence that the fine-tune works. The tuned model is not on the machine I ran this from, so both columns below are two base models: qwen3-8b in the "base" column and qwen3.5-9b in the "tuned" column. I used them to test the harness itself. The real comparison is in its own section below.

The project

A pipeline that fine-tunes Qwen2.5 on applied statistics (Poisson and negative binomial regression, SARIMA, hypothesis tests, fraud modelling) using QLoRA on an 8 GB RTX 4060. It generates 240 training pairs locally, reviews them with an automated gate, trains and exports to Ollama. What it lacked was any measurement of whether the tuned model beats the base.

The harness

  1. Held-out questions the model never trained on, each with accepted keywords.
  2. Exact McNemar test on paired pass/fail, written with math.comb, no stats library.
  3. A separate judge model (gpt-oss-20b) that grades each answer 1 to 5 against a reference answer (hard set) or the keyword list (easy set), then a paired sign test.
  4. One model loaded at a time, because alternating models on 8 GB of VRAM crashed the server.
  5. Unit tests for keyword matching, a known McNemar value, failed calls never passing, and both question files.

The lesson. A harness that reports a number is not a harness that works. The 5% looked like a finding until I read the answers.

Hard, n = 1989% vs 84%, McNemar p = 1.04.05 vs 4.47, sign test p = 0.69 (qwen3-8b better on 2, qwen3.5-9b on 4, 13 tied)
  • The easy set could not tell the models apart, so it stopped being useful. The hard set has a reference answer for every question.
  • The two methods pointed opposite ways: keywords favoured qwen3-8b, the judge favoured qwen3.5-9b, and they flatly contradicted each other on 3 of the 19 hard questions. That is why I report both.
  • Only 3 questions split the models on keywords (6 on the judge). The exact test cannot reach p < 0.05 with fewer than 6 split questions all going one way, so the next set needs more hard questions.

The real comparison

The original adapter was lost, so I retrained it: same recipe (QLoRA on Qwen2.5-7B-Instruct, the 240 training pairs, 1 epoch, 108 steps, final training loss 1.484, eval loss 1.18; the first run had reported 1.49 and 1.16). This is a re-run, not the adapter from the first run. Both columns are the same 4-bit base model, with the adapter switched on or off, greedy decoding and the Qwen chat template. The answer cap went from 400 to 1024 tokens, and I wrote 24 more hard questions (73 in all) so that enough questions could split to make the exact test usable.

  • No measurable difference. Keyword pass is 90% for both. Exactly 6 questions split the models, 3 each way, so the exact McNemar test gives p = 1.0.
  • Tuned answers were shorter: about 1,200 characters against 1,930 for the base, on the first 49 questions.
  • I have no judge result. The judge I could reach for free (a 30B NVIDIA model) gave a 5 to almost every answer on the first pass. With a stricter prompt and a larger token budget it returned a score for only 15 of 49 answer pairs, so I discarded it rather than report a number.

What I would claim, and what I would not

I would claim: the harness runs end to end, treats failed calls safely, and reports "not significant" when that is the answer. On 73 held-out questions the retrained fine-tune is no better than its base on keyword pass rate.

I would not claim: that the fine-tune beats its base, that it is worse, or that the first two base models differ. Not claimed either: that the original adapter behaves the same as the retrained one. The reference answers and keywords are mine and have not been reviewed by a statistician, one judge model is one opinion, the first 49 answers were capped at 400 tokens and some were graded unfinished (the retrained comparison used 1,024), one training run is one seed, and I matched eval questions to the training set by exact text only, not by paraphrase.
